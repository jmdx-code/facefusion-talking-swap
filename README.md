# FaceFusion 口播换脸（Windows NVIDIA 独立便携版 & 云表格协同工作台）

基于 **FaceFusion 3.9.0** 深度定制的口播视频换脸独立便携工作台，内置一键场景预设、严格的本地隐私隔离（`userdata/`）、首次启动官方源自动环境与模型初始化，以及多人协同的 **Google Sheets + Google Drive 云表格自动接单中心**。

---

## 快速下载与使用（普通用户直接看这里）

> **无需手动安装 Python、CUDA、FFmpeg 或 Git**，解压后外层只有 **启动 / 停止 / 说明** 三个按钮，零门槛上手：

1. 前往本仓库右侧 **[Releases](../../releases/latest)** 页面，下载 **`FaceFusion-Portable-Windows-NVIDIA.zip`**（仅约 **12 MB** 极简便携包）。
2. 解压到任意文件夹（建议所在磁盘预留 ≥ 15 GB 可用空间用于缓存运行环境与模型）。
3. 双击 **`启动FaceFusion.cmd`**：
   - **首次启动全自动初始化**：控制台窗口会自动从官方国际源（GitHub Official Releases / PyPI / HuggingFace）依次安装 FFmpeg、Python 与 NVIDIA CUDA 12 / cuDNN 9 运行库及口播所需 AI 模型，全程支持字节级断点续传与 SHA-256 / CRC32 校验（安装一次永久缓存，第二次起秒开）。
   - **启动自动热更新**：每次打开时自动检测最新在线版本并秒级同步约 `0.4 MB` 热更新包（网页右上角 **🔄 检查在线热更新** 只检查；停止后重新启动自动安装），个人配置、Google 授权与已下载模型 100% 保留。
   - **自动打开界面**：就绪后浏览器自动打开 `http://127.0.0.1:7860`。
4. 使用完毕双击 **`停止FaceFusion.cmd`** 即可关闭后台服务。

### 硬件与系统要求
- **操作系统**：Windows 10 / Windows 11（64 位）
- **显卡要求**：NVIDIA 独立显卡（RTX 20 / 30 / 40 / 50 系列、GTX 16 / 10 系列等，建议显存 ≥ 6 GB，推荐 ≥ 8 GB），已安装 **NVIDIA 官方显卡驱动**（建议驱动版本 ≥ 531）
- **内存建议**：≥ 16 GB

## 核心功能亮点

- **双模式极简 Web 界面**
  - **🎬 手动精细换脸**：三步极简流程（① 上传源人脸图与目标视频 → ② 一键选择场景预设 → ③ 开始处理），成品自动保存在 `userdata\manual_outputs`，专业参数折叠在底部“高级参数微调”。
  - **📋 云表格任务中心**：对接 Google Sheets 多人协同领单，支持动态表头识别（任意挪列、插行、排序均不错行）、并发抢单冲突校验、FFprobe 智能检测与按需标准化转码（`H.264 + yuv420p + AAC`）、成品自动上传 Google Drive 并回填共享链接、自动单条接续领取（完整完成后立即检查并领取下一条，无任务时每20分钟再查，不预领排队任务）及断网保底补传。
- **口播实战一键预设**
  - `✨ 没问题选这个`：恢复原默认（`inswapper_128_fp16`、Pixel Boost `128x128`、权重 `0.5`、上下半脸恢复 `80`、`gfpgan_1.4` 混合 `65`、box遮罩，关闭太阳穴修正和原口腔回填）
  - `旧模型`：与当前默认完全相同，保留名称兼容已有表格任务
  - `👄 解决嘴巴张不开`：针对口播张嘴受限优化（仅下半脸表情恢复 `100` + `gfpgan_1.4` 混合 `30`）
  - `👀 解决眼睛斜`：针对眼神偏移优化（关闭上半脸恢复，保留下半脸恢复 `80` + `gfpgan_1.4` 混合 `65`）
- **严格隐私与数据隔离（`userdata/`）**
  - 程序绝不读取本机电脑主机名，工位名称由用户自行填写（如 `Alex`、`Worker-01`）。
  - 所有 Google OAuth 凭证、工位配置、自定义预设、自动下载的 `.onnx` 模型、临时帧缓存、运行日志与成品视频全部隔离在根目录 `userdata\` 文件夹内，不写注册表、不污染系统盘。

## 安全与供应链策略

- **纯官方国际源直连**：环境组件、模型下载与云端接口仅连接 `https://pypi.org`、`https://files.pythonhosted.org`、`https://huggingface.co`、`https://github.com` 与 `https://*.googleapis.com`，不使用任何第三方镜像源。
- **双重哈希防篡改校验**：每个下载的运行库 `.whl` 与 `.onnx` 核心模型均强制校验官方 **SHA-256** 密码学摘要与 CRC32 `.hash` 清单，任何损坏或篡改文件自动拦截清理。
- **本地回环隔离与防 SSRF**：Web 工作台默认仅绑定 `127.0.0.1` 并启用上传缓存路径沙箱；云表格外部素材下载内置逐跳重定向 SSRF 防护与 FFmpeg 本地协议白名单。
- **敏感凭证硬隔离**：本地 OAuth 令牌自动收紧当前系统用户专属读写权限；打包器与 `.gitignore` 强制排除 `userdata/` 及一切凭证密钥文件。

## 默认方案与更新兼容

自1.3.5起，手动启动、默认预设、云表格空白/“默认”/“没问题选这个”均恢复原InSwapper完整画质方案；“旧模型”和内部键`clear`与默认一致。自定义预设不覆盖。保留按需帧率/编码标准化、默认开启且可关闭的1080p放大、人脸区域30秒分段FFV1无损缓存、分步并发和自动清理。1080p放大会改变处理输入像素和资源需求，可按素材关闭；省空间缓存不额外修脸。

标准单人、无身份/年龄/性别筛选且权重0.5的任务使用分步并发：人脸定位 → 换脸 → 表情恢复 → 增强与太阳穴修正重叠执行。按接任务时的空闲显存选择档位；不把整段视频缓存到内存。自1.3.0起，中间数据只保存原像素尺寸的人脸区域，使用30秒分段FFV1无损RGB视频；不再保存整段原始PNG或全画面BMP。身份匹配、筛选、其他处理器等设置自动沿用兼容流程。

1.3.1增加“高+”档：空闲显存≥8500MiB时，换脸10路、表情恢复5路、增强5路、太阳穴10路；人脸定位维持8路。原高档（≥5000MiB，8/4/4/8）、中档（≥3600MiB，4/2/2/4）和低档不变，8GB显卡不会进入高+档。高+档尚未在12GB显卡上实测速度和显存峰值，初始档位按任务开始时的余量选择。

1.3.2增加显存不足自动降档：默认FFV1视频流程识别CUDA显存分配失败后，关闭当前任务的FFmpeg进程，释放模型会话和临时缓存，按“高+→高→中→低”降低上限并重新处理该视频。画质、模型、分辨率、编码参数不变。由于上一步缓存会逐段删除，重试从头开始；已完成的其他任务不重做。一个任务只降不升，下个任务重新测量显存。最低档仍失败即明确报错，不循环重试；停止操作不触发重试。系统内存不足、磁盘不足、编码失败和其他模型错误不归入显存降档。该能力覆盖默认视频管线，不覆盖高级兼容管线或单图流程。已通过真实视频流程的错误注入恢复测试，尚未故意占满真实显存验证。

1.3.4针对6GB显卡（检测总显存大于5120、至多6144MiB）将中档门槛降为3200MiB，并将最高档限制为中档；不足3200MiB用低档。8GB及以上门槛不变。每条任务重新检测，只计算专用显存，运行中OOM仍逐档回退。手动和云表格页面每2秒刷新当前档位、各工序并发、任务进程专用显存、观测峰值及整卡余量。Windows通过GPU进程计数器统计处理进程及编码子进程；结束后保留峰值，新任务重新计数，编码重试保留同一任务的峰值。计数器不可用时明确显示不可读取，不用整卡占用冒充任务占用；共享内存不计入。手动页面统计所在Python进程及其子进程，可能包含同进程预览保留的模型会话；峰值为采样观测值。

启动补齐当前内置预设所需模型，不再强制下载非默认的1a；已有模型和授权保留。模型缺失/损坏会重新校验下载；断网时保留已安装版本及下载断点。网页内不覆盖正在运行的程序；更新包先完整校验并暂存，替换失败回滚，版本号最后提交。

低分辨率输入：当前“输出缩放”是在换脸和增强后放大；预先把360p放大到1080p再处理，会在更大的画布上保留模型生成的人脸细节，效果可能比360p处理后再放大清晰。它不能恢复原素材中不存在的真实细节；现已提供默认开启的“低分辨率视频提升至1080p”开关，在抽帧时等比放大；关闭后保持原尺寸，1080p及以上不缩小。开关保存于`userdata/video-options.json`，手动和自动接单共用。

## 1.2.1 临时文件回收

视频/图片流程使用finally统一关闭读写进程、释放帧缓存并删除临时帧，覆盖成功、失败、中止和异常路径。手动标准化转码目录也随任务清理。工作目录带进程归属标记；强制退出留下的目录在停止程序或下次启动时回收，仍存活的进程目录不会删除。旧版未标记的本程序临时目录在过期24小时后启动回收；系统Temp中其他安装或归属不明的目录保留。

Gradio上传缓存仍按12小时过期规则清理，并保护当前选中的源图和目标视频。保留模型、下载断点、授权、原素材、任务记录、手动成品和接单保底成品。任务运行时的临时磁盘高占用属于处理中间数据，1080p放大会增加峰值；结束后自动回收。

## 1.2.2 预览与资源回归修复

修正实时预览和普通图片/视频流程的scale_face导入，以及普通流程缺少get_middle导入；太阳穴修正兼容BGRA预览并保留透明度。浏览器由外层启动器统一打开一次。

兼容流程在抽帧前按处理分辨率、帧数估算全尺寸帧空间上限；不足时自动转到低并发流式处理，不保存整段帧，也不以JPEG替代无损中间数据。流式流程限制待处理帧队列，保留同一模型和强度设置，速度可能降低。1.3.0的新默认流程不使用这项全尺寸帧预算。

成功校验的模型缓存路径、大小、修改/创建时间、校验文件状态和固定SHA摘要；未变化时复用，变化时重新计算CRC32和SHA-256。`python -m facefusion.model_bootstrap --check-only --verify-all`可强制全量检查。网页更新继续只检查、重启安装；手动选择其他模型时按需下载。

## 1.3.0 人脸区域与30秒分段FFV1

手动制作与自动接单默认共用新管线：原视频流式解码并换脸 → 人脸区域FFV1 → 下半脸恢复 → 人脸区域FFV1 → 增强、太阳穴修正、编码 → 恢复音轨。中间区域保持原像素尺寸，FFV1采用无损RGB，不做JPEG压缩或色度抽样。最终视频继续使用用户设定的编码器、质量、帧率和尺寸。

30秒仅决定缓存文件的分界；每个模型阶段连续处理整段视频，不每30秒重载模型。后一步完成一个分段后立即删除对应的上一步缓存，最后编码消费完一个分段也立即删除。正常完成、失败、中止均关闭所创建的FFmpeg进程并清理；强制退出的残留在下次启动回收。原始素材、模型和成品保留。

缓存大小随人脸占比、运动和画面内容变化。此前该WhatsApp素材1080p一分钟实验的FFV1峰值约584MiB；按同类素材预估五分钟中间缓存约2.1～2.3GiB，建议额外预留成品及转码空间。这是素材估算，不是所有视频的固定上限。缓存写入空间不足时，释放缓存后回退到低并发流式兼容流程。
